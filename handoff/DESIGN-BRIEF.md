# V3 → Figma Make 视觉迭代交接

这是一份设计与实现任务书。导入包以现有第三版为起点，原始工程和素材保留在用户电脑上。这里记录既有审美问题和验收要求，不代表本包已经在 Figma 内安装、运行或完成改版；具体打包与测试结果以包内 README 和验证记录为准。

## 目标与事实边界

网站属于魏一鸣，服务于长期的个人表达、作品归档和专业机会。它同时呈现景观、商业平面、摄影、UE/Blender、植物图册、AIGC 影像、Web/UI 七个维度，不预设唯一职业身份。审美目标是让不同媒介形成一个人的连续叙事。

- 参考：[Gianluca Gradogna](https://gianlucagradogna.com/)、[作者在 Codrops 的案例说明](https://tympanus.net/codrops/2025/01/30/case-study-gianluca-gradogna-portfolio-25/)。
- 学习其版面秩序、字图关系、动效节奏与连续观看方式；不复制作者身份、照片、文案或商业字体文件。
- 原站不是每一屏全黑：深色首页和作品环境与明亮摄影章节形成变化。当前目标也不是泛化的米白色作品集模板。
- 原站是否使用某一种严格的共享元素变形，既有检查没有充分证实。不要把“原站一定这样做”当作实现依据；项目展开的连续性是我们自己的设计目标。
- 现有作品事实、制作贡献、AI 辅助说明、复刻说明、进行中状态需要保留。首页可更抽象，详情需要准确。
- 摄影尚未选入。Studio、东涌、西九调研照片不作为个人摄影作品补位。

## 现有工程基线

主站是 React 18、Vite 6、GSAP 的客户端工程，使用 hash 路由。优先阅读 `src/main.jsx`、`src/components/HomeV3.jsx`、`src/components/home-v3.css`、`src/v3.css`、`src/lib/motion.js` 和项目数据。

桌面宽度 ≥801px 使用虚拟滚动坐标与双向取模循环。≤800px 使用原生线性滚动，是现有适配选择，不是本次导入丢掉了无限滚动。保留 Full/Reduced 和系统减少动态偏好。首页打开项目后关闭，应恢复原浏览位置。

首页已有六个精选项目：

| ID | 当前作用 | 首页展示名草案，尚待审美确认 |
|---|---|---|
| `graphic-k-black` | 商业平面视觉 | 商业图像 / Commercial Images |
| `spatial-moroccan-courtyard` | 三维空间场景 | 光与空间 / Light & Space |
| `living-edge` | 景观设计与研究 | 边界与生境 / Edges & Habitats |
| `dune-remake` | AIGC 影像 | 异境 / Otherworlds |
| `plant-reference` | 植物图册与编辑 | 植物图志 / Botanical Atlas |
| `sleeve` | 唱片封面编辑 UI | 可玩的界面 / Playful Interfaces |

展示名应该增加独立的首页字段或映射，不覆盖 canonical ID 和详情真实标题。无需把内部型号、系列名称、工具或“网页”这些标签放到最大字号，但也不使用虚假的宏大项目名包装小练习。

## 完整问题清单

这是整体路线图。A 阶段做深三个设计样本，B 阶段把规则推广；C 阶段单独打磨详情页。用户可以将全部要求交给 Make 一次读取，分阶段不是技术限制。

| 优先级 / 阶段 | 目前不足 | 希望如何改善 | 可检查的结果 |
|---|---|---|---|
| P0 / A | 首屏有形式上的白卡、深色背景，但层次与焦点不够统一 | 统一近黑、深蓝绿、白卡和少量明暗重点，调整左右视觉重量 | 同视口看首屏，第一视线有明确落点，背景不灰糊，白卡与环境互相支撑 |
| P0 / A | 人像虽已换为黑白近景，明亮颈部仍占据注意力 | 重裁切、压暗、遮罩和细颗粒，使发丝、耳后、颈肩成为抽象材质 | 不再像生活照加卡片；保留人物特征而不是整张面孔主导 |
| P0 / A | 海边戴墨镜生活照同时出现在首页和菜单，与目标气质不一致 | 两处都移除；用现有作品的材质、物件、页面或光影细节替代 | 首页及菜单不再出现该生活照，替代图与主色调一致 |
| P0 / A | 右侧废寺背景偏平灰，小图片和大标题关系生硬 | 为背景建立前后明暗与留白；重新设计字、图和局部的共同构图 | 字不依赖大遮罩才能读清，小图不是随手插入的装饰 |
| P0 / A | 英文字体的字形和光学比例未成熟；中文主要靠缩放适配 | 分别设定中英的字重、字号、行距、字距、断行和辅助标签层级 | 同一视口切换中英，两种语言都无挤压、孤字和错位 |
| P1 / A | 0→100 存在，但可能只是附加的计数动画 | 将资源就绪、计数、遮罩、背景、白卡与文字编成完整开场 | 首次进入流畅；Reduced 快速进入；不把长等待伪装成设计 |
| P0 / A | 每个作品封面主要还是一个 `<img>`，缺少针对网页的构图 | 先为商业视觉定制分层封面，以真实素材局部建立尺度与节奏 | 不依赖整张成稿缩小贴图，也不把同张带字图模糊铺满背景 |
| P0 / A | UI 封面仅为截图，用户无法体验自己做的功能 | 使用真实 Sleeve 的模板、文字、颜色编辑；呈现可交互窗口 | 三种操作都改变实际预览，重新进入不会出现假按钮或失效输入 |
| P0 / A | 嵌入 UI 可能与无限滚动竞争滚轮和焦点 | 设计显式进入、退出；展示态滚动归首页，交互态明确边界 | 鼠标、键盘、触屏均能退出；退出后原滚动位置与焦点合理恢复 |
| P0 / A | 图片按章节整数切换，标题、编号与背景像分开播放 | 让连续局部滚动进度驱动层次关系，设计进入、停留和离开 | 慢滚有过程、快滚不漏帧式闪变、反滚自然回退 |
| P1 / A | 同方向固定时长遮罩用于不同滚动方向 | 采用可逆的进度关系，减少与滚动无关的定时动画 | 正反两个方向都不会逆着手势强行向上播放同一揭幕 |
| P1 / A | 悬浮大多只有很小的平移，既弱又缺少目的 | 商业图可显示细节/第二视角；文字链接可展示对应图；位移克制 | 指向不同内容有可理解反馈；移开平滑回位，不产生全站晃动 |
| P0 / A | 无限循环在功能上成立，末章仍有“已经结束”的页脚感 | 将末章视觉收束为下一次首屏的铺垫，协调接缝前后背景与版面 | 连续正向两圈、反向一圈，无硬跳、白闪、重复叠字或停住 |
| P1 / B | 六张封面虽然不同内容，却几乎采用同一种矩形贴图 | 为场景、图纸、册页、影像分别设计可复用的不同展示规则 | 每类拥有合适尺度，但文字、编号和动效仍属同一个系统 |
| P1 / B | 部分命名是文件名或内部产品型号，陌生观众难理解 | 使用能力型首页展示名，保留准确详情与制作说明 | 一眼知道“商业视觉/空间/UI”等方向，而无需先懂型号 |
| P1 / B | About、空摄影框、目录连续出现，后半段能量下降 | 调整章节长度、留白、密度和视觉呼应；减少空位的过重戏剧化 | 后半程仍有节奏，真实缺项保留但不占据整站高潮 |
| P1 / B | 菜单、目录、作品侧栏的字号与对齐尚未完全统一 | 用 A 阶段确定的排版规则覆盖导航与信息层级 | 中文、英文、数字、按钮在不同场景保持统一基线和可读性 |
| P1 / B | 手机只是缩小后可能失去封面重点 | 为触屏重新排布焦点、正文和交互入口，保持原生滚动 | 390/320px 无横向溢出，不依赖 hover 才能理解内容 |
| P2 / C | 项目展开更像打开新的黑色页面，入口与内容缺少关联 | 后续探索从入口构图延续的揭开与关闭，必要时再评估共享元素 | 返回时位置、焦点与视觉方向连续；不以未经证实的原站技术为依据 |
| P2 / C | 宽幅渲染、册页、UI 都接近同一展示高度，容易像黑底贴图 | 按媒体类型设计尺度、留白、跨页、视频播放与翻页节奏 | 每类作品得到适合的阅读方式；本轮暂不深入详情内容 |

## A 阶段明确交付

1. 一个完成度更高的中英首页：深色氛围、人物抽象构图、明确字图层次、0→100 开场。
2. 一张用现有 `graphic-k-black` 素材完成的商业视觉封面，带有意义的悬浮反馈。
3. 一个与网站构图融合的真实 Sleeve 交互封面，能够选模板、改文字和配色，且能进入、退出完整体验。
4. 上述场景与相邻场景的可逆滚动过渡，以及双向无限循环接缝；其余作品保持可访问。
5. 运行通过的代码、真实执行的测试清单、截图或观察依据、仍待处理的 B/C 阶段问题。

Sleeve 的可编辑源码位于 `examples/sleeve`；预构建演示路径为 `/demos/sleeve/index.html#/templates`。它与主站的 React/Vite 版本不同，优先保持独立边界。演示页的现有能力需要实际运行核对；不要因为目录存在就声称功能已经验收。任何第三方示例图片仍保持原有归属，不计为用户摄影。

## 数据与实现保护

- 保留全部 44 条项目记录及现有三条占位状态，不能为凑满页面将占位改成真实成果。
- 保留 EN/ZH 切换、七类目录、简历与联系方式、制作贡献说明，以及已存在的页面路由。
- 首页展示名可以变，但项目详情的真实项目名与 AI/复刻信息不能消失。
- 保留 Full/Reduced、系统减少动态偏好、键盘操作、可见焦点、弹层关闭与位置恢复、浏览器历史行为。
- 不因导入而重建框架，不为炫技增加大型 WebGL 场景。当前核心问题是美术编排与时序。
- 预览视频仅用于轻量导入和设计判断，最终清晰度使用本地保留的原片恢复。Figma 无法从这个上传包读到电脑其他文件夹。
- 主站现有视觉不能被大面积演示假数据替换。若需要额外素材，列出所需局部和用途，先用包内真实素材完成可行范围。

## 具体验收矩阵

| 检查项 | 执行方式 | 通过条件 |
|---|---|---|
| 可构建 | 按 README 安装并构建主站；改动 Sleeve 时也构建它 | 无构建错误；新的依赖和锁文件一致 |
| 双语 | 1440/1280 宽度分别切换中英 | 切换立即生效，标题不遮挡，导航无混乱，视觉完成度相当 |
| 开场 | 刷新首次进入，分别用 Full/Reduced | 不无限等待；资源未到也有合理处理；进入后可立即操作 |
| 连续滚动 | 慢滚、快滚、反向滚动经过两个重点封面 | 无突兀索引硬换、黑白闪帧、错误方向动画或两份文字叠加 |
| 无限循环 | 桌面向下连续两圈，再向上跨过接缝 | 不中断、不跳到另一布局、接缝前后构图连贯 |
| 真实 UI | 改模板、文字、颜色，再退出体验 | 预览真实变化，退出控件始终可用，首页恢复原位置 |
| 项目路由 | 打开项目、关闭、浏览器前进/后退 | 不丢当前位置，不留下遮罩或不可点击界面 |
| 手机 | 390/320 宽度，用触屏操作替代 hover | 无横向溢出、按钮过小、内容遮挡；原生滚动可用 |
| 无障碍动态 | Reduced 和系统减少动态偏好；Tab/Enter/Escape | 反馈明确，焦点不进入不可见场景，不困在 UI 或菜单 |
| 原站对照 | 相同视口看首页、商业封面、UI 封面和循环接缝 | 给出具体差异；不能只说“更高级”或未经核验声称完全复刻 |

## 如果选择一次让 Make 改完整站

可以把完整清单一次交给同一个 Make 会话，工程本身不是障碍。建议仍要求它按 A → B → C 顺序实现、每阶段构建和体验、保留版本。A 阶段确定的是封面构图、字图比例和滚动关系；这些没有稳定之前，直接把同样的错误批量复制到六张封面，返工会更大。

用户当前授权的具体提示词默认止于 A。若用户决定一次完成 A+B，可把提示词中的范围段替换为：

> 本轮执行 A 和 B 全部条目。先完成三个样本并自检，再将一致的视觉和动效规则推广到其他封面、About、摄影留白、目录、菜单及手机适配。保留全部作品、双语和桌面双向循环；按阶段保留版本并列出测试结果。C 阶段项目详情页暂不深入。

这比只说“全部变高级”更容易得到可检验的结果，也不限制日后继续修改。
